# Иконки плейлистов каталога

Иконка — необязательное поле `icon` плейлиста в `manifest.json` (формат — `docs/author-manifest-example.json`).

```json
{
  "id": "morning-soft",
  "name": "Утро: мягкий старт",
  "icon": "icons/morning-soft.png",
  "description": "Спокойное утро без спешки.",
  "tracks": [
    {
      "title": "Тихий рассвет",
      "artist": "Пример исполнителя",
      "duration": 180,
      "url": "https://example.com/audio/morning-1.mp3"
    }
  ]
}
```

**Где лежит PNG.** `icon` — https-адрес или путь от адреса манифеста. Для
`https://github.com/anichivo/playlists/raw/main/manifest.json`
путь `icons/morning-soft.png` даёт
`https://github.com/anichivo/playlists/raw/main/icons/morning-soft.png`
(файл — в репозитории `anichivo/playlists`, папка `icons/`; список файлов:
`https://github.com/anichivo/playlists/tree/main/icons`). GitHub отвечает
редиректом на raw-хост, приложение следует редиректам.

**Требования.** PNG; прозрачный фон; одна фигура; рекомендуется 128×128 px;
до 256 КБ. Цвет не важен — приложение тонирует иконку цветом темы,
важен только альфа-канал.

**Смена иконки.** Загрузите файл с НОВЫМ именем и обновите `icon`: кеш
привязан к адресу, по тому же адресу иконка не перекачивается.

**Поведение.** Нет `icon` или файл не скачан/не декодировался → нейтральная
запасная иконка; каталог и воспроизведение не страдают. Новые иконки
скачиваются при следующем обновлении каталога (вкладка «Каталог» → «обновить»);
обновление приложения не нужно. Скачанные показываются и без сети.
«Любимое» всегда показывает встроенное сердечко, каталог на него не влияет.
