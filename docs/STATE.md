# Состояние проекта: VibraTuner

Gradle 9.1.0, AGP 9.0.1, Kotlin 2.3.20, Java toolchain 17 (сборка проверена на JDK 25); `minSdk 31`, `compileSdk/targetSdk 36`. Версия `versionName 1.0`, `versionCode 1`.

Проверка: `gradlew.bat --quiet assembleDebug testDebugUnitTest` — код 0; 655 тестов в 74 наборах, 0 падений (30.10.2026). Debug APK — `app/build/outputs/apk/debug/app-debug.apk`; release — `app/build/outputs/apk/release/app-release.apk`.

## Сделано

- Собрано приложение v1.0: пять разделов («Звуки», «Микрозвуки», «Расписание», «Эквалайзер», «Настройки»), сеансы с точными будильниками, микрозвуки с окнами и «Часами тишины», каталог «От автора», скачивание плейлистов, импорт файлов/папок, глобальный мини-плеер, эквалайзер, прерывистая музыка, «Включение колонки» и фейк-включение.
- Room-схема доведена до версии 13; миграции 3 → 4 → … → 13 покрыты `AppDatabaseMigrationsTest`.
- Реализованы проверка обновлений GitHub Releases, экран «Надёжность», единое уведомление воспроизведения и возврат системной громкости после сбоя процесса.
- Документация актуализирована перед публикацией: `AGENTS.md`, `README.md`, `.agent/rules/project-rules.md`, `docs/STATE.md`.

## Принятые решения и причины

- **Java toolchain 17.** `sourceCompatibility`/`targetCompatibility = 17`, `jvmToolchain(17)`. Gradle запускается на установленном JDK 17+ (проверено на JDK 25) и сам скачивает Temurin JDK 17 для toolchain, если его нет; отдельная установка JDK 17 не требуется, но нужна сеть.
- **Рукописный SQLite вместо кодогенерации Room.** Room используется только как контракт аннотаций; DAO и `SQLiteOpenHelper` написаны вручную, чтобы не зависеть от kapt/ksp и нестабильных версий процессоров. Схема и миграции проверяются тестами.
- **Один сервис и один координатор.** Вся логика воспроизведения, приоритеты и оба плеера живут в `SoundPlaybackService`; второй путь воспроизведения запрещён правилами.
- **Настройки в одном DataStore.** `vibra_tuner_preferences` хранит громкость, прерывистую музыку, часы тишины, эквалайзер, сессию, флаги первого запуска, проверку обновлений и резерв системной громкости.
- **Только тёмная тема.** Палитра Anthropic/Claude, токены в `theme/`; светлой схемы и переключателя темы нет.
- **Правила проекта опубликованы.** `.agent/rules/project-rules.md` добавлен в git принудительно (`git add -f`), поэтому доступен в публичном репозитории, хотя `.agent/` целиком исключён в `.gitignore`; остальные файлы `.agent/` (skills) не публикуются.
- **Подпись release необязательна.** `signingConfigs.release` создаётся только при наличии `keystore.properties`; ключ и пароли хранятся вне репозитория.
- **Проверка обновлений по умолчанию выключена.** Сеть — только после явного согласия; проверка не чаще раза в сутки из `VibraTunerApplication.onCreate`, без WorkManager и фоновых сервисов.
- **Нет рекламы, аналитики и учётных записей.** Сеть используется только для каталога «От автора» и проверки обновлений.

## Известные проблемы

- **Debug и release подписаны разными ключами.** Перед установкой release debug-сборку нужно удалить; данные приложения при этом теряются.
- **`release-out/` не создаётся Gradle.** `assembleRelease` кладёт APK в `app/build/outputs/apk/release/app-release.apk`; файл `release-out/vibratuner-v1.0.apk` существует, но Gradle-задачи для его копирования нет. При публикации ориентируйтесь на вывод `assembleRelease`.
- **Устаревшие комментарии в коде.** В `MusicScreen`/`MainScreenLayout` и `Dimens.kt` встречается «Моя медиатека», хотя UI и строки используют «Моя коллекция». Это косметика; код вне рамок документационной задачи и не менялся.
